# Архитектура

Термины — в `GLOSSARY.md`.

## Стек

| Область | Выбор | Почему |
|---|---|---|
| Фреймворк | Next.js (App Router) + React 19 + TypeScript (strict) | Практика на Next, серверная предзагрузка, превью ссылок (ADR 0006) |
| Карта | MapLibre GL JS + `react-map-gl/maplibre` | Открытый, без токена Mapbox (ADR 0002) |
| Подложка карты | OpenFreeMap (стиль `liberty`) | Бесплатные векторные тайлы без ключа |
| Серверный слой | Серверные функции + Route Handlers `/api/stations*` | Токен и формат WAQI только на сервере (ADR 0007) |
| Серверное состояние на клиенте | TanStack Query + `HydrationBoundary` | Кэш, повторы, статусы; сервер заполняет начальный кэш (ADR 0003, 0006) |
| URL-состояние | nuqs (shallow) | Типизированные параметры без серверного рендера на каждый клик (ADR 0003) |
| Настройки пользователя | cookie | Язык виден серверу и не навязывается ссылкой (ADR 0008) |
| i18n | next-intl без i18n-маршрутизации, `ru` (по умолчанию) и `en` | Работает в RSC и клиенте, типизированные сообщения (ADR 0008) |
| Таблица | TanStack Table | Headless, сортировка/фильтрация |
| Тесты | Vitest, React Testing Library, MSW, Playwright | Unit, компонентные, e2e |
| Деплой | Vercel | Нативная платформа Next |

## Структура

Роутинг Next лежит в корневой `app/` и остаётся тонким. Весь код — в слоях Feature-Sliced Design в `src/`. Next ищет `app/` и `pages/` сначала в корне, затем в `src/`. Корневая `app/` скрывает `src/app`. Чтобы так же скрыть `src/pages`, в корне лежит пустая папка `pages/` (только README). Без неё Next принимает `src/pages` за Pages Router, и сборка падает.

```
app/                          # роутинг Next: только реэкспорт и вызовы из src/
  layout.tsx                  # <html lang>, провайдеры из src/app
  page.tsx                    # export { default, generateMetadata } from '@/pages/map'
  api/
    stations/route.ts         # GET → список станций Бишкека (доменный формат)
    stations/[uid]/route.ts   # GET → детали станции (доменный формат)
pages/                        # пустая (README): не даёт Next принять src/pages за Pages Router
i18n/
  request.ts                  # next-intl: язык из cookie, по умолчанию ru
src/
  app/            # провайдеры (QueryClient, NuqsAdapter, NextIntlClientProvider), глобальные стили
  pages/
    map/          # Server Component страницы: предзагрузка, HydrationBoundary, generateMetadata
  widgets/
    app-header/   # название и переключатель языка
    air-map/      # карта со слоем станций и кластерами (client, next/dynamic ssr:false)
    station-panel/# панель: список станций или карточка выбранной станции
    stations-table/
    aqi-legend/
  features/
    select-station/   # ?station через nuqs
    search-stations/  # ?q через nuqs, debounce
    switch-language/  # RU | EN, запись cookie
  entities/
    station/
      model/      # доменные типы, свежесть данных (общий код)
      api/        # клиентские хуки useStations / useStation → /api/stations*
      server/     # server-only: getBishkekStations(), getStationDetails(uid) — WAQI → домен
  shared/
    api/waqi/     # server-only: http-клиент WAQI с токеном, типы ответов, валидация
    lib/aqi/      # уровни AQI, диапазоны, цвета (без текстов)
    i18n/         # словари messages/ru.ts (эталон) и messages/en.ts, типизация сообщений
    ui/           # базовые компоненты
    config/       # константы: границы Бишкека, порог свежести, URL стиля карты
```

Правила:
- Слой может импортировать только из слоёв ниже. Между слайсами одного слоя — только через `index.ts`.
- Серверный код слайса экспортируется отдельной точкой входа (`entities/station/server`), чтобы клиентский `index.ts` не тянул `server-only`.
- Модули с `WAQI_TOKEN` и походами в WAQI начинаются с `import 'server-only'`: импорт такого модуля из клиентского кода ломает сборку.

## Рендеринг

- `src/pages/map` — **Server Component**. Он вызывает `getBishkekStations()`, а при `?station=` ещё и `getStationDetails(uid)`. Результаты кладутся в `QueryClient` и передаются клиенту через `dehydrate` + `HydrationBoundary`. Шапка и панель (список или карточка) приходят готовым HTML.
- **Карта** — клиентский компонент через `next/dynamic` с `ssr: false`. Пока она грузится, на её месте скелетон.
- **`generateMetadata`** читает `searchParams.station` и отдаёт `title` и OG-описание вида «US Embassy — AQI 180, вредно» на языке пользователя. Без выбранной станции метаданные общие.
- Страница динамическая (cookie языка, `searchParams`, живые данные). Кэширование — на уровне `fetch` к WAQI и `Cache-Control` Route Handlers.

## Раскладка

- **Шапка** (~48px, и на мобильном тоже): «Bishkek Air» слева, переключатель **RU | EN** справа (кнопки с `aria-pressed` и `lang`).
- **Панель** в одном из двух режимов:
  - **список станций**, если `?station` нет;
  - **карточка станции** с кнопкой «← Ко всем станциям», которая снимает выбор.
- **Десктоп**: панель слева от карты. **Мобильный**: нижняя шторка с тремя состояниями:
  - `peek` — поиск и строка «хуже всего сейчас: <станция>, AQI»;
  - `half` — список станций или карточка;
  - `full` — весь список.

  При выборе станции шторка переходит в `half`, карта сдвигает точку в видимую часть. В MVP шторка переключается кнопкой-ручкой, без жестов.
- **Легенда** — компактная полоска цветов поверх карты (на мобильном над шторкой). По клику или Enter раскрывается поповер с уровнями, диапазонами, рекомендациями и ссылкой на AirNow.
- **Атрибуция**: «Данные: WAQI» в контроле атрибуции карты рядом с OpenFreeMap/OSM; источники станции — в карточке.
- **Клавиатура**: путь через список станций (Tab → поиск → строки → Enter выбирает, Esc закрывает карточку). Точки на карте не фокусируемые, у контейнера карты `aria-label` с подсказкой про список.

## Данные

### Поставщик данных (WAQI)

Только серверный слой (`shared/api/waqi`, `entities/station/server`) ходит в WAQI:

- `map/bounds?latlng=<lat1>,<lng1>,<lat2>,<lng2>&networks=all` — станции в прямоугольнике: координаты, `uid`, `aqi`, название, время.
- `feed/@<uid>/` — детали станции: общий `aqi`, `dominentpol`, `iaqi` (показатели по загрязнителям), `time`, `attributions`, `forecast.daily` (в MVP не используется).

Особенности, которые важно учесть:
- `aqi` в `map/bounds` приходит строкой и может быть `"-"`, если данных нет. В домене это `aqi: number | null`.
- Значения в `iaqi` — это **индексы AQI по каждому загрязнителю**, а не концентрации в мкг/м³. Подписывать в UI нужно соответственно.
- В `iaqi` есть и погода (`t`, `h`, `p`, `w`, `wg`, `dew`). Маппер оставляет только шесть загрязнителей, остальные ключи отбрасывает.
- Опечатка `dominentpol` — так в API, в домене называем `dominantPollutant`.
- Названия станций приходят латиницей с хвостом `..., Bishkek, Kyrgyzstan`. Маппер отрезает хвост, не переводит.
- Атрибуция (`attributions`) обязательна к показу. В домене это `sources` (источники станции).
- Одна физическая станция может прийти из двух сетей. В MVP не дедуплицируем, при ручной проверке фиксируем в PR.
- WAQI отвечает `200` со `status: "error"` при ошибке. Серверный слой превращает это в ошибку, Route Handler отдаёт `502`.

### Наши эндпоинты (ADR 0007)

| Эндпоинт | Ответ | Ошибки |
|---|---|---|
| `GET /api/stations` | `Station[]` — станции Бишкека | `502`, если WAQI недоступен или ответ не прошёл валидацию |
| `GET /api/stations/[uid]` | `StationDetails` | `400` — невалидный uid, `404` — станции нет, `502` — WAQI |

Ответы в доменном формате, с `Cache-Control: s-maxage=300, stale-while-revalidate=600`.

### Станции Бишкека

`shared/config`: прямоугольник примерно `42.78,74.45 — 42.95,74.75`, центр карты `42.8746, 74.5698`, начальный zoom 11–12. Список станций запрашивается **один раз** по этому прямоугольнику и не перезапрашивается при сдвиге карты. `maxBounds` карты чуть шире прямоугольника. Точные координаты уточнить по данным при реализации.

Ссылка на станцию вне прямоугольника всё равно открывает её карточку (`feed` работает по uid). Если станции нет (`404`), в панели показывается «Станция не найдена» с кнопкой «Ко всем станциям», URL сам не очищается.

### Доменная модель

```ts
type AqiLevel = 'good' | 'moderate' | 'sensitive' | 'unhealthy' | 'very-unhealthy' | 'hazardous';

type Pollutant = 'pm25' | 'pm10' | 'no2' | 'so2' | 'o3' | 'co';

type Freshness = 'fresh' | 'stale' | 'no-data';

interface Station {
  id: number;            // WAQI uid
  name: string;          // без хвоста «, Bishkek, Kyrgyzstan»
  coordinates: { lat: number; lng: number };
  aqi: number | null;
  level: AqiLevel | null;
  updatedAt: string | null; // ISO, момент последнего измерения
}

interface StationDetails extends Station {
  dominantPollutant: Pollutant | null;
  pollutants: Partial<Record<Pollutant, number>>; // индексы загрязнителей
  sources: { name: string; url: string }[];       // источники станции
}
```

**Свежесть** (`Freshness`) не хранится в станции, а вычисляется при рендере из `aqi`, `updatedAt` и текущего времени: `no-data`, если `aqi === null`; `stale`, если измерение старше порога (`shared/config`, 3 часа); иначе `fresh`. **«Сейчас»** для свежести и относительного времени («12 минут назад») — одно значение на весь экран, а не `Date.now()` в каждом компоненте. Сервер фиксирует `now` в момент запроса и передаёт его клиенту (опция `now` в next-intl и тот же `now` для свежести), поэтому гидратация совпадает. Дальше `now` обновляется вместе с данными: это `dataUpdatedAt` из TanStack Query при каждом перезапросе. Без таймеров и `useEffect`; между перезапросами подписи не тикают.

Как свежесть влияет на отображение:
- **Карта**: цвет и число AQI только у `fresh`. Точки `stale` и `no-data` серые, без числа.
- **Кластер**: цвет — худший уровень среди `fresh` станций внутри; если таких нет — серый.
- **Список станций**: группы идут в порядке `fresh` → `stale` → `no-data` при любой сортировке. Внутри групп по умолчанию AQI ↓, `no-data` — по названию. У `stale` серая плашка и пометка «устарели».
- **Карточка**: у `stale` показывается последнее значение с датой («данные от 20 ноября, 14:00»).

### Уровни AQI (шкала US EPA)

| AQI | Уровень | Цвет |
|---|---|---|
| 0–50 | Хорошо | `#00e400` |
| 51–100 | Умеренно | `#ffff00` |
| 101–150 | Вредно для чувствительных групп | `#ff7e00` |
| 151–200 | Вредно | `#ff0000` |
| 201–300 | Очень вредно | `#8f3f97` |
| 301+ | Опасно | `#7e0023` |

`shared/lib/aqi` хранит только уровни, диапазоны и цвета. Подписи и рекомендации лежат в словарях (`aqi.levels.<level>.label` / `.guidance`): в `en` оригинальные формулировки AirNow, в `ru` их перевод.

### Кэширование

- Сервер → WAQI: `fetch(..., { next: { revalidate: 300 } })`.
- Route Handlers → клиент: `Cache-Control: s-maxage=300, stale-while-revalidate=600`, CDN Vercel отдаёт кэш.
- TanStack Query: `staleTime` 5 минут для списка станций и деталей, 2 автоповтора при ошибке. `refetchOnWindowFocus` по умолчанию включён: при возврате на вкладку протухшие данные перезапрашиваются. Таймерное автообновление — после MVP.

## Состояние

- Серверные данные на клиенте — TanStack Query (`entities/station/api`). Начальный кэш заполняет сервер.
- Выбранная станция — `?station=<uid>` через nuqs (`parseAsInteger`, `history: 'replace'`, shallow). Карта, список и панель читают одно и то же значение, поэтому синхронизация обходится без общего стора.
- Поиск — `?q=` через nuqs с debounce. Фильтрует только список, карта всегда показывает все станции.
- Язык — настройка пользователя в cookie. Если её нет, язык русский, язык браузера не учитывается (ADR 0008). Смена языка пишет cookie и делает `router.refresh()`, чтобы сервер перерисовал тексты.
- Локальный UI (состояние шторки) — `useState` в компоненте.

## i18n

- next-intl без i18n-маршрутизации. `i18n/request.ts` читает язык из cookie, по умолчанию `ru`.
- `shared/i18n/messages/ru.ts` — эталон. `en.ts` типизирован формой `ru`, а сообщения объявлены глобально для next-intl, поэтому пропущенный или ошибочный ключ — ошибка `tsc`.
- Один набор сообщений, ключи сгруппированы по слайсам (`stationList.*`, `stationCard.*`, `aqi.levels.*`, …).
- Даты, относительное время и числа — форматтер next-intl с `timeZone: 'Asia/Bishkek'`.
- Подписи подложки карты: `coalesce(name:<lang>, name)` в выражении стиля при загрузке.

## Тесты

- **Unit (Vitest):** `shared/lib/aqi`, маппер WAQI → домен, свежесть, сортировка списка.
- **Route Handlers:** вызываются как функции (`GET(request)`) с замоканным `fetch` к WAQI: успешный ответ, `status: "error"`, невалидный ответ, `404`.
- **Компоненты (RTL + MSW):** только клиентские компоненты. Хелпер `renderWithProviders` даёт `QueryClient`, `NextIntlClientProvider` (`ru`) и `NuqsTestingAdapter`.
- **Async Server Components** через RTL не тестируются: их логика вынесена в функции под unit-тесты, страницу целиком проверяет Playwright.
- **E2E (Playwright):** запросы к WAQI идут с сервера, поэтому перехват в браузере не поможет. Playwright поднимает два `webServer`: маленький мок-сервер с JSON-фикстурами WAQI и прод-сборку Next (`next build && next start`) с `WAQI_BASE_URL`, указывающим на мок. Те же фикстуры используются в unit-тестах маппера.
- **`WAQI_BASE_URL`** — единственная уступка тестам в коде приложения: базовый URL WAQI читается из env, по умолчанию `https://api.waqi.info`.

## Пустые состояния и ошибки

| Ситуация | Что видит пользователь |
|---|---|
| Список станций не загрузился (после 2 автоповторов) | Подложка карты на месте; поверх неё и в панели «Не удалось загрузить станции» + «Повторить» |
| Пришло 0 станций | В панели «Сейчас нет данных ни по одной станции» и ссылка на поставщика данных |
| Нет ни одной станции со свежими данными | Карта серая, над списком плашка «Данные всех станций устарели» |
| Карточка не загрузилась | Ошибка и «Повторить» в карточке; список и карта работают |
| `?station=` на несуществующую станцию | «Станция не найдена» + «Ко всем станциям» |

Если серверная предзагрузка упала, страница всё равно рендерится, а TanStack Query повторяет запрос на клиенте и показывает те же состояния.

## Производительность

- Станции рендерятся одним GeoJSON-слоем MapLibre (WebGL), а не React-компонентами-маркерами.
- Кластеризация — встроенная в GeoJSON source (`cluster: true`). При выборе станции из списка или по ссылке карта приближается до зума, где кластеры раскрыты.
- Карта — отдельный клиентский чанк (`next/dynamic`), не блокирует HTML со списком станций.
- Все оптимизации — с замерами «до/после» в PR.
- Цели (≤ 2 с до станций, Lighthouse ≥ 90) замеряются на проде и фиксируются в README. Блокирует только Accessibility < 90.
