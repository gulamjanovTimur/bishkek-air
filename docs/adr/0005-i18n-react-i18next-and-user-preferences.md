# 5. Двуязычный интерфейс на react-i18next, настройки пользователя в localStorage

**Статус:** принято

## Контекст
Интерфейс нужен на русском и английском с первой версии. Если добавлять второй язык потом, придётся переписывать каждый компонент. Язык — это личная настройка пользователя, а не состояние экрана. Отправитель ссылки не должен навязывать получателю свой язык, поэтому URL (ADR 0003) не подходит. Три категории состояния из ADR 0003 (сервер, URL, локальный `useState`) эту настройку не покрывают.

## Решение
- Две локали, `ru` и `en`, на react-i18next. Обе загружаются статически в бандл, без загрузки словарей по сети.
- Один namespace, ключи сгруппированы по слайсам. Эталон — `ru`, а `en` типизирован формой `ru`. Ключи `t()` проверяются компилятором через `CustomTypeOptions`.
- Тексты, которые зависят от языка (подписи уровней AQI, рекомендации), живут в словарях. `shared/lib/aqi` хранит только уровни, диапазоны и цвета.
- Вводим четвёртую категорию состояния — **настройки пользователя** (язык, позже тема). Они хранятся в localStorage и намеренно не попадают в URL.
- Язык берётся из localStorage, если там ничего нет — русский. Язык браузера не учитывается.

## Последствия
- Пропущенный перевод или опечатка в ключе — ошибка `tsc`, а не пустая строка в проде.
- Ссылка на станцию открывается у получателя на его языке.
- Множественное число, относительное время и форматы чисел — через i18next и нативный `Intl`, свои утилиты не нужны.
- Третий язык (например, кыргызский) добавляется новым словарём без изменения компонентов.
