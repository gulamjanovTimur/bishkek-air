# 6. Next.js App Router вместо Vite SPA

**Статус:** принято, заменяет ADR 0001

## Контекст
ADR 0001 выбрал SPA на Vite: страница одна, SEO почти не важен. Но у проекта есть цель, которую ADR 0001 не учитывал: получить практический опыт на Next.js. Кроме того, серверный рендер даёт продукту реальную пользу:
- список станций приходит готовым HTML ещё до загрузки карты (цель «≤ 2 с до станций»);
- ссылка на станцию показывает превью с названием и AQI в мессенджерах (сценарий «Поделиться»).

## Решение
Next.js (актуальная стабильная версия) с App Router, деплой на Vercel.
- `page.tsx` — Server Component. Он загружает список станций (и детали при `?station=`) и передаёт их в TanStack Query через `dehydrate` + `HydrationBoundary`.
- Карта — клиентский компонент через `next/dynamic` с `ssr: false`.
- `generateMetadata` формирует заголовок и OG-описание выбранной станции.
- Роутинг Next лежит в корневой `app/` и остаётся тонким. Слои FSD лежат в `src/` (Next их как роутинг игнорирует).

  > **Уточнение (issue #2):** Next ищет `app/` и `pages/` сначала в корне, затем в `src/`, поэтому `src/app` и `src/pages` игнорируются, только если в корне есть и `app/`, и `pages/`. В корне лежит пустая `pages/` (только README). Без неё Next принимает `src/pages` за Pages Router, и сборка падает. Само решение не меняется.
- Модули, которые ходят в WAQI, помечаются `import 'server-only'`.

## Последствия
- Больше движущихся частей, чем у SPA: граница сервер/клиент, гидратация, кэш Next. Это сознательная плата за практику.
- Async Server Components не тестируются через Vitest/RTL: логику из них выносим в функции под unit-тесты, страницу целиком проверяет Playwright.
- Прокси из ADR 0004 и хранение языка из ADR 0005 пересмотрены под сервер: ADR 0007 и ADR 0008.
